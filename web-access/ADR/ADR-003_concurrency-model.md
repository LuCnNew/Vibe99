# ADR-003 — Multi-Client Input Policy (Revised: Free-Write)

> **BLUF**：决定多客户端采用**自由写入**——任一已连接客户端都可向任一 pane 输入。本版**修订原 v1** 的"每 pane 单一活跃写入者（claim）"模型；URD 明确单用户单工作站，冲突概率可忽略。

## Context

Phase 2 加速：多客户端纳入范围，需定输入资格。原 v1 的 claim 模型前提是"防多人冲突"；但 URD 约束为**单用户、单工作站**——物理上不会两台设备同时敲键。

## Options Considered

- **自由写入**（任一已连接客户端可向任一 pane 输入）
- **focus-claim**（每 pane 单一活跃写入者，原 v1；其余只读，按 focus 自动接管）
- 多写入者合并 ≡ 自由写入（同义）

## Decision

**自由写入**：任一已连接客户端可向任一 pane 输入。修订 ADR-003 v1。

## Consequences

- **优点**：最简单，无"接管/释放"UI，无摩擦；契合单用户（一人一键盘，碰撞 ~nil）。
- **代价**：两客户端若同时输入，字节交错进入同一条 pty 流（单用户可接受）。
- **备注**：修订 v1；claim 模型作为文档化选项保留，若将来引入多用户再启用。多客户端尺寸冲突另见 ADR-005。
