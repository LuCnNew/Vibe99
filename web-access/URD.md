# URD — Vibe99 Web Access

> **BLUF**：本需求定义"用网页浏览器打开 Vibe99 终端工作区、并在任何能接入 VPN 的地方，继续此前在桌面开启的多窗口 agentic-coding 会话"要解决什么问题、面向谁、用户能得到哪些保证。本文只描述**问题空间**，不涉及任何技术实现选型。

## Rationale

**Problem definition**

用户在桌面用 Vibe99 同时开多个终端窗口/pane 跑 agentic-coding 任务（agent、长命令等）。一旦离开本机（出差、换设备），这些窗口和正在运行的任务无法被远程接续——Vibe99 是一个桌面应用，其终端会话与"本机前台窗口"绑定，关掉即终止。用户希望：输入一个网址，就能从浏览器回到**同一组窗口、同一批正在运行的任务**。

**Value proposition**

让"在桌面上开始的多窗口工作"成为一个可在任何地点通过浏览器**无缝接续**的持久工作会话；并且本地与远程可以**同时**使用同一会话，而非二选一。

## Users & Scenarios

**Target users**

单人开发者（本机拥有者），以 agentic-coding 为主，习惯同时开多个终端窗口/pane 进行多任务。

**Usage contexts**

- **在桌面前**：本机用浏览器访问 `127.0.0.1:<port>`（原生桌面应用为可选遗留客户端），开启多窗口多任务。
- **出差/外出**：通过 VPN（主机 `10.8.0.154`）用任意设备的浏览器访问，继续之前的多窗口会话。
- **本地与远程同时**：本机与远程浏览器同时连接到同一工作区。

## Scope & Appetite

**Functional boundaries**

- 为 Vibe99 增加"网页可达 + 会话持久 + 多客户端并发"三项能力。
- 保留 Vibe99 既有的多 pane、focus-first 工作区体验。
- 不改变用户既有的 shell 环境与任务本身。

**Project time budget**

大（数周）。采用**深度改造路线**（把 Vibe99 工作区改造为浏览器可直接访问、会话持久、支持多客户端的形态），而非短期临时包装方案。

## User Requirements (Desires + Constraints)

**Desires**

- 只在浏览器输入网址即可打开 Vibe99 工作区，无需在访问端安装客户端。
- 打开后看到的是本机此前开启的多窗口/pane 布局，且其中正在运行的任务（agent、长命令）仍然存活，可立即接续输入与查看输出。
- 本地（桌面）与远程（浏览器）能同时连接到同一工作区。
- 远程体验接近本地：文本清晰、输入低延迟、可滚动查看历史输出。

**Constraints**

- **访问地址**：同一端口——本机经 `127.0.0.1:<port>`、远程经 VPN `10.8.0.154:<port>` 访问；默认不在公网暴露。
- **单用户、单工作站（本机）**：非多租户、非多人协作平台。
- **运行环境**：本机 Linux 工作站（Vibe99 现有支持的平台）。

## User Guarantees

- **会话存续**：终端任务在本机持续运行，与"是否有客户端连接"无关；客户端断开后重新连接，回到的是**同一个活着的会话**（任务未中断）。
- **接续不丢内容**：客户端（重新）连接后，能看到该 pane 的历史输出（scrollback），而非空白屏幕。
- **并发一致**：多个客户端同时连接时，看到的是同一份会话状态；输出对所有客户端一致。
- **访问受控**：仅授权/可信网络（VPN）内的访问可到达工作区；未授权访问被拒绝。
- **体验下限**：在 VPN 网络条件下，文本终端的显示与输入延迟处于可接受范围（量化阈值见 `VERIFICATION_PLAN.md`）。

## Deferred Requirements

- **主机重启后自动恢复会话**（需进程级韧性兜底承载）——列为后续阶段。
- 移动端 / 小屏专项优化。
- 公网暴露与多用户/团队协作（账号、权限、隔离）。
- 非终端（图形/音频）应用的支持。
- 会话/输出的加密审计与长期归档。
